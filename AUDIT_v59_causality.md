## Этапы

### 1. Решение
- **Сейчас.**
  - Strategy: `switch()` ~1771, исследование — `thompson()` ~1845.
  - AA: `AI.pick` ~3325 (исследование тоже Thompson), `AI.set` ~3346.
  - Phase: `side_note`.
  - Evo: `E.force`.
- **Сломано.**
  - У решения нет ID.
  - Propensity Thompson sampling аналитически не считается: вероятность выбора не записана и не может быть записана.
  - С v57 эксперименты и испытания Evo в журнал не попадают вовсе (`NOT_VERIFIED` ~3345).
  - «Решено» и «применено» не разделены: guard (v58), safe head, manual подменяют профиль, и в данных это никак не отражено.
- **Исправление.**
  - `L.decide(sys, key, n_opt, chosen, p, reason)` → `decision_id`, кольцевой буфер на 300 записей.
  - Исследование становится ε-равномерным: выбранный вариант получает `p = (1-ε)·[лучший] + ε/K`, для детерминированных смен `p = 1`.
  - Решения guard записываются с эффективной propensity для данного контекста.
  - Эксперименты и Evo записываются (`verify = false`), но вердикт «до / после» для них не выносится.

### 2. Снимок контекста
- **Сейчас.** `enemy_shot_start "aa ctx"` ~2928 берёт `AA.cur_index` **текущего** тика. `flip_at` / `profile_mixed` используют историю `S.fh`: максимум 40 записей, только тики отправки и всего 3 поля.
- **Пример отказа.** Профиль сменился на 2 тика раньше, чем пришёл `bullet_fire`. Враг стрелял по старому профилю, а награду получает новый. Пометка `mixed` ставится только для окна 0.25 с.
- **Исправление.** Кольцевой буфер на 256 тиков, массивы чисел без аллокаций. В каждом тике пишутся: профиль, сторона, guard, недавний phase-reset, состояние ideal tick, defensive, freestanding, режим AA, скорость и choke.
  - Выстрел врага выравнивается на `t − (ping + interp + choke)`.
  - Профиль, сторона и флаги берутся из **выровненного** тика.
  - `mixed` = профиль менялся в окне ±1.5 тика вокруг выровненного момента.

### 3. Выстрел
- **Сейчас.** Выстрел врага собирается из `bullet_fire` / `impact` / `hurt` (~741–900), у него есть пометка `burst`. Наш выстрел сопоставляется по `aim_fire.id`.
- **Сломано.** Нет `shot_id`, нет качества сопоставления, нет группы независимости. Вторая пуля DT учится как отдельный выстрел с весом 0.3, но в ESS считается как независимая.
- **Исправление.**
  - `shot_id` на каждый выстрел.
  - `mq` (качество сопоставления): `fire+impact`, `impact`, `hurt`, `fire+impact+hurt`.
  - `grp` (группа независимости): серия DT одного стрелка; для наших выстрелов — серия DT и цикл ideal tick.

### 4. Атрибуция
- **Сейчас.** `ST.attribution` ~1979 и `AI.attr` ~3479 — ручные веса.
- **Сломано.** Для AA нет базовой линии. С v58 (guard) эксперименты идут только в «лёгких» контекстах — это смещение отбора. Нет поправок на phase-reset и телепорт ideal tick.
  - Strategy: «действовала» проверяется только по источнику голоса, но не по тому, отличалось ли значение от того, что поставил бы Default.
- **Исправление.**
  - **AA:** обучение по **преимуществу** `y − E[y | контекст]`. Базовая линия — иерархическая с усадкой: бакет (оружие × дистанция × ты двигаешься × враг двигается × вердикт guard) → (оружие × дистанция) → общая.
  - Новые множители: phase-reset ×0.6, ideal tick TELEPORT/RETURN ×0.3, defensive ×0.6.
  - **Strategy:** `effective = false`, если значение голоса совпадает с вашим значением в меню (его можно прочитать при override, если `get()` ≠ `get_override()`).
  - Каждая атрибуция записывает читаемые причины.

### 5. Взвешенный выборка
- **Сейчас.** Нет. Каждая система сама копит свои счётчики.
- **Исправление.**
  - Одна запись на `shot_id` с полями: `did`, `sid`, бакет, `y`, `b`, `adv`, `w`, `p`, `pred`, `grp`.
  - Запись идемпотентна: повторный вызов с тем же `shot_id` игнорируется.
  - Kish ESS = (Σw)² / Σ W_g², где W_g — сумма весов группы независимости: коррелированные выстрелы не добавляют n.

### 6. Уверенность
- **Сейчас.** Три разные формулы: `ST.p_better`, `AI.p_better`, `DL.judge`. В Strategy дисперсия включает приор по популяции (вес 10), поэтому после одного выстрела бывает «confident 91%» — это видно в вашем выводе `/eclipse why`.
- **Исправление.**
  - Общая функция `L.p_better(m1, v1, m2, v2)` с поправкой калибровки.
  - `L.level`: «prior only», если собственный ESS меньше `min_samples`.
  - Уверенная смена требует собственного ESS у обоих вариантов.
  - `/eclipse calib`: таблица надёжности по децилям, Brier score и наклон калибровки. Если наклон < 1 (переуверенность), z-оценки сжимаются.

### 7. Проверка
- **Сейчас.** `DL.judge` ~1226 — «до / после», смешано со временем: враги и карта меняются вместе со сменой. `/eclipse replay` симулирует политику только на совпавших решениях; эксперименты не проигрываются.
- **Исправление.**
  - `/eclipse replay` по умолчанию — **OPE**: SNIPS и DR-lite (базовая линия + SNIPS по преимуществу) по записям с propensity, отдельно для Strategy и AA. Для каждого варианта: эффективное n, оценка и 95%-интервал. Старая симуляция доступна как `/eclipse replay legacy`.
  - Вердикты «до / после» сохраняются, но в них пишутся метод, ESS, разница и интервал с пометкой «confounded by time».

### 8. Обучение
- **Сейчас.** Обновления разбросаны по трём хукам и побочному каналу `ai_reward`.
- **Исправление.**
  - Learners читают только `rec.sample` (вес, преимущество, группа). Его создаёт один хук на канал (prio 5) — до learners.
  - AA: оценка = базовая линия группы + усаженное среднее преимущество (`L.acc`); старые счётчики `bd` — приор весом 4.
  - Strategy: Beta по `vh` / `vm` (доля HP).

### 9. Обнаружение изменения поведения
- **Сейчас.** Только затухание; классификатор AA перезапускает RELEARNING при смене типа.
- **Исправление.** Page-Hinkley по преимуществу для каждого врага, отдельно для наших выстрелов и для его выстрелов.
  - Срабатывание по нашим выстрелам → RELEARNING Strategy для этого врага.
  - Срабатывание по его выстрелам → его статистика AA ×0.5.
  - Обе записи с причиной (`DL.note kind="cp"`).
  - Строки журналов получают `rv` (версия награды, 2 = доля HP с v58), чтобы `report` не сравнивал несравнимое.

## Риски v57–v59

1. **Guard = смещение отбора.** Подтверждено. В тесте `tests/sim` raw-доли уворотов дают неверный порядок профилей. → Базовая линия по бакету с вердиктом guard + propensity по контексту. В опасном контексте у не-лучших профилей `p = 0` (нет перекрытия) — **OPE для них там невозможна**, это сказано прямо; сравнение идёт внутри бакетов.
2. **Незаписанные смены (v57).** Подтверждено (~3345). → Записываются с propensity, без вердикта.
3. **Случайный сброс фазы (v58).** → Флаг в снимке (окно 0.3 с), вес ×0.6, фактор в отчёте.
4. **Телепорт ideal tick.** → Состояние ideal tick в снимке. Выстрел врага в TELEPORT/RETURN — вес ×0.3. Наши выстрелы в ideal tick помечаются `itc` (циклом) и группируются.
5. **Смешение наград (v58).** **Найдена ошибка с двойным счётом.** После v58 каждый выстрел пишется **и** в h/m, **и** в vh/vm, а ESS в `ST.post` = ESS(vh) + 0.25·ESS(h) — один выстрел засчитывается как 1.25. Шкалы тоже разные: h — доля попаданий (≈ 0.5), vh — доля HP (≈ 0.35). Смешение тянет среднее вверх у «попадающих» вариантов, то есть у тела.
   - → При миграции h/m **замораживаются** в `lh` / `lm` (приор старых данных, только затухание). Новые выстрелы идут только в vh/vm; h/m копятся дальше лишь для отображения.
   - **Ещё ошибка:** при провале уверенной стратегии (~2071) ослабляются только h/m, а vh/vm (по ним с v58 принимаются решения) — нет. Исправляется.
6. **Голова: политика / стратегия 8.** `ST.effective` пропускает голоса `head:` для стратегий 2/8 — верно. Но если значение совпадает с вашим, выстрел всё равно засчитывается стратегии. → Проверка «отличается от вашего» (этап 4).
7. **Prior-only.** Подтверждено вашим выводом («confident 91%, 1 samples»). → `L.level`; смены и состояние CONFIDENT требуют собственного ESS.

## Что честно не стоит своей сложности при текущем объёме данных (несколько сотен выстрелов за сессию)

- **Полный doubly robust с обученной моделью исхода.** Модели не на чем учиться. DR-lite (бакетная базовая линия + SNIPS по преимуществу) даёт ту же защиту от смещения при меньшей дисперсии.
- **Propensity для Thompson.** Исследование заменено на ε-равномерное: та же доля экспериментов, но вероятность выбора известна точно.
- **Базовая линия для Strategy.** Варианты Strategy назначаются цели, а не контексту: смещения отбора как у guard здесь нет. Базовая линия и преимущество записываются в выборку (для OPE и обнаружения изменений), но Beta Strategy учится по доле HP, иначе добавилась бы дисперсия без снижения смещения.
- **Per-enemy AA по преимуществу.** На одного врага приходится 5–20 выстрелов за сессию. Оставлено с сильной усадкой (k = 10).
